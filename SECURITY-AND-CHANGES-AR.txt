ios app: التعديلات ونتائج الفحص

النتيجة
نسخة مصدر معدّلة باسم ios app بواجهة iPhone جديدة وأيقونة جديدة وإصلاحات أمنية ووظيفية محددة. ليست IPA مبنية أو موقّعة، وليست شهادة بخلو المشروع من الثغرات. نجحت الاختبارات المحمولة مع 618 مدخلًا في كل تشغيل. Swift وObjective-C وربط Xcode لم يُختبر بالبناء هنا.
المشروع ما زال يشغّل أندرويد على iOS. تغيير الواجهة لا يحوّل APK إلى تطبيقات iOS ولا يلغي JIT ومتطلبات الذاكرة.

قارئ DEX
أُصلحت قراءات خارج حدود الملفات في src/translation-layer-next/husk-tl-dexindex.c. أضيف التحقق البنيوي للرأس ومحاذاة الإزاحات وحدود الجداول والفهارس ونهاية السلاسل وأعضاء الفئات وأحجام بيانات التعليمات. ULEB128 محدود بخمسة بايتات وبحدود الملف. أُصلح تنظيف الحالات الفاشلة وحساب مجموع الفئات عند إضافة APK آخر. يستدعي قارئ DEX القديم التحقق البنيوي نفسه قبل تكوين مؤشرات داخل الملف.
هذا ليس verifier كاملًا للـ bytecode. مفسّر التعليمات وELF/JNI/JIT يحتاجون تدقيقًا أوسع. التنفيذ داخل عملية التطبيق ليس sandbox.

التنزيل والمستودعات
أُصلح عمر ملف URLSession المؤقت: يفحصه الكود وينقله قبل انتهاء callback، لا داخل مهمة لاحقة قد تعمل بعد حذفه.
يُشترط HTTPS وتُرفض بيانات الدخول داخل الرابط وredirect إلى HTTP. تُفحص حالة HTTP وSHA-256 قبل التثبيت. أسماء الملفات المحلية UUID بدل حقول المستودع. تُتحقق أسماء الحزم، وتُحفظ مراقبة التقدم ويعمل الإلغاء وتظهر أخطاء التنزيل.
يُرفض الفهرس الأكبر من 64 MB وAPK الأكبر من 2 GB بعد وصولهما. هذه ليست حدودًا أثناء الاستقبال؛ تحتاج حدود استهلاك الشبكة والقرص أثناء التنزيل إلى عمل إضافي.
البصمة من المصدر نفسه تثبت التطابق معه، لا موثوقيته المستقلة. لم تُضف مصادقة توقيع فهرس F-Droid. مصادر JSON البسيطة تحتاج sha256 لكل تطبيق، وإلا يُستبعد التطبيق.

الأوامر والملفات
أُزيل أمر shell المبني على اسم حزمة المستودع من DiscoverTab.swift. التشغيل عبر AndroidHost.launch مع التحقق واختيار نشاط الإطلاق بدل افتراض MainActivity. أضيف التحقق قبل الإزالة وجلب المعلومات والتحقق وإزالة التكرار في القوائم المحفوظة والواردة.
في HuskBridgeFS.swift يحافظ اقتباس المسارات على الاقتباس المفرد بطريقة POSIX بدل حذفه. أضيف الاقتباس لمسارات قاعدة بيانات الأيقونات وWAL. هذه إصلاحات لمواضع محددة، وليست إثباتًا بتدقيق كل أوامر المشروع.

ZIP والشبكة وصورة الضيف
أضيف CRC وتطابق الاسم وطريقة الضغط والأعلام بين local وcentral headers، والتحقق من نهاية EOCD ورفض multi-disk. أُصلح فك deflate الفارغ والتحقق من استهلاك المدخل.
أُغلق السماح العام بـ HTTP للمضيف، وطبقة HTTP الأصلية تتطلب HTTPS مع تحقق من المدخلات وبعض حالات فشل التخصيص. قد يمنع هذا تطبيقات تعتمد HTTP القديم. شبكة الضيف عبر QEMU منفصلة عن ATS.
يتحقق GuestManifest.swift من أسماء الملفات والأجزاء والبصمات والأحجام وإعدادات الآلة وقائمة CPU مدعومة. لا يُعاد digest ناقص عند خطأ قراءة. فحوص التحديثات لا تتداخل وتتباعد عشر دقائق بعد النجاح.

الواجهة والهوية
الاسم الظاهر ios app، الإصدار 0.6.2، البناء 10. أُعيد رسم جميع الأيقونات الأساسية والبديلة ونسخ المعاينة، 1024×1024 وبدون شفافية. SVG داخل design/ ومولّدها scripts/redesign_icons.py.
المكتبة شبكة أيقونات iPhone بدون بطاقات ثقيلة، والإعدادات قائمة iOS مجمعة جديدة. تغيرت شاشة الترحيب والإقلاع والأزرار والعناوين المشتركة. التصميم فاتح مع بنفسجي هادئ، وحُفظت خيارات المظهر الموجودة والعربية وRTL.
أُعيد شريط التبويبات. فتح التطبيقات من الاكتشاف يعرض الضيف، والواجهة المخفية لا تعترض لمسه. التقدم مراحل مرصودة ووقت منقضٍ بدل زيادة مصطنعة أو وعد غير مثبت بوقت متبقٍّ.
حُفظت أسماء target والمشروع ومعرّف الحزمة ومفاتيح البيانات الداخلية، وحقوق Husk وترخيص GPL.

الأداء
الأيقونات تُقرأ وتُصغّر خارج الخيط الرئيسي، مع cache 32 MB و256 صورة ومقاس فك مناسب للعرض. فك JSON خارج الخيط الرئيسي، وقوائم الاكتشاف lazy، وفحوص التحديثات لا تتداخل، وسجلات QEMU الافتراضية أخف.
لم يُقَس زمن التشغيل أو FPS على iPhone. هذه تغييرات تقلل العمل المتكرر، وليست إثباتًا لتحسن بعدد ثوانٍ محدد.

ما اختُبر
python3 tests/security_regression.py: نجاح 618 مدخلًا مع UBSan.
ASAN=1 python3 tests/security_regression.py: نجاح المدخلات نفسها مع AddressSanitizer وUBSan.
الحالات ZIP المخزن والمضغوط والفارغ واختلاف CRC والأسماء وDEX القصير والجداول غير الصالحة وULEB128 التالف و600 تعديل عشوائي ببذرة ثابتة.
نجح XML لكل plist وentitlements وJSON لفهارس الأيقونات وsyntax لسكربتات Bash والتحقق من مقاس الأيقونات وRGB. أُصلح تعليق XML غير صالح في Info.plist. أُزيلت مواضع snappy وtoolbar الخاصة بـ iOS 17 للحفاظ على هدف iOS 16.4.

ما لم يُحسم
تشغيل APK الأصلي داخل عملية التطبيق أخطر مسار. أضيف إقرار بالمخاطر قبل تفعيله، لكن الإقرار ليس حماية تقنية.
لم يُبنَ Swift/Objective-C أو تُوقّع IPA أو يُختبر الصوت والجرافيكس واللمس والذاكرة على الجهاز. البيئة لا تحتوي Xcode أو iOS SDK ولا اتصال إنترنت.
لم تُفحص مكتبات الجهات الخارجية مقابل قواعد بيانات الثغرات ولا أصالة upstream IPA التي يجلبها workflow. اختبارات parser لا تغطي كل opcode أو ELF/JNI/QEMU/JIT. لا يوجد حد أثناء استقبال كل استجابة HTTP ولا تدقيق شامل لكل تخصيص ذاكرة أو تضارب خيوط.
استخدم APK موثوقة فقط في التشغيل الأصلي. يلزم البناء واختبارات الجهاز وتدقيق أوسع قبل الاستخدام الإنتاجي.
